# Autonomous TCR–pMHC model research — initial objective

## Task

You are an autonomous ML research agent. Your goal is to improve prediction of whether a T-cell receptor (TCR) binds a peptide–MHC (pMHC) complex, using **amino-acid sequence inputs only**.

**`ml.py` is the only existing source file you may modify.** It contains the initial, intentionally simple model and training implementation. Treat it as the starting point, not an architectural constraint. You have full freedom to replace or redesign the model architecture, feature representation and optimisation approach **within `ml.py`**, including MLPs, CNNs, transformers, attention, protein language model encoders or representation-learning objectives, subject to the available compute and libraries. Do not alter the underlying dataset, splits, evaluation definitions or experimental runner.

**Editable surface during autonomous research: `ml.py` and one append-only log, `experiments/evaluation.log`, only.** Create that log and its parent directory if absent; do not create additional source files, summaries, JSON ledgers or context files. `eval.py`, this objective, the controller, dependencies and datasets are read-only to the research agent. Existing training outputs such as `model.pth` may be generated by executing `ml.py`; this is not permission to edit other files manually. Configure training within `ml.py` to append its training events to the same shared log instead of overwriting a separate training log. Do not overwrite or delete previous log entries.

Use scientific best practice to improve the model: formulate falsifiable hypotheses, make controlled changes, check implementation validity and interpret the complete evaluation evidence. You may choose the architecture, representation, optimiser and training loss. The loss used to train a model is distinct from the fixed, comparable validation loss computed by `eval.py`. Do not change the evaluation protocol to improve the apparent score.

Decisions must consider validation loss together with overall AUROC, AUPRC, peptide-level and category-specific performance, class counts, possible overfitting and computational cost. No single metric automatically determines acceptance. Prioritise credible generalisation evidence, and justify trade-offs explicitly in the log. A small change in a small subgroup is not sufficient evidence of improvement; use repeat seeds for promising or ambiguous results within budget.

## Fixed evaluation contract

Run training using the existing entry point, then evaluate the saved checkpoint:

```bash
python ml.py
python eval.py --experiment_dir experiments/1/ --experiment-id EXP_0001 --hypothesis "Specific falsifiable hypothesis" --change "Exact change made to ml.py"
```

Use the actual checkpoint directory if it differs from the starter default. `eval.py` creates/appends `experiments/evaluation.log` automatically. Use this same log path for every experiment; do not create a separate history per run. Read the entire evaluator report before interpreting results.

Preserve the existing interface while redesigning internals: `ml.Model()` reconstructs the saved model and `forward(peptide, hla, tcr)` returns one finite binding probability in [0, 1] per row; `ml.Dataset(path)` exposes `.data` in original CSV row order and returns `(peptide, hla, tcr, binding_flag)`. Keep input columns and labels in `.data` unchanged. The fixed evaluator selects eligible full-chain rows itself and independently checks returned labels against the CSV. Training in `ml.py` must use the same eligibility checks. Use full sequences without truncation: inspect the starter padding limits and correct them within `ml.py` before claiming a full-chain baseline; negative padding can otherwise crop long sequences. Architecture freedom does not include silently changing row membership, targets or the evaluator interface.

`eval.py` reports:

- Overall AUROC (ROC AUC), AUPRC (average precision), accuracy at threshold 0.5, MSE/Brier score and binary log loss. `validation_loss` is the fixed, sample-weighted probability MSE; this remains comparable even if the training loss changes. It is not a requirement to train with MSE. Binary log loss clips probabilities to [1e-7, 1-1e-7].
- The same metrics **for each peptide**, with row counts, positive/negative counts and prevalence; unweighted peptide-macro AUROC and AUPRC across peptides with both labels, plus coverage/exclusion counts.
- The same metrics **for every supplied category value**, preserving its name (for example unseen TCR, unseen HLA or completely unseen). It recognises common category column names; use `--category-column COLUMN` if the name differs or multiple candidates exist. Missing annotations are reported as a group. If no category column is available, this limitation is explicit.
- When `TRAIN_PATH` is available, separately derived overlapping seen/unseen groups for TCR, peptide, HLA and pMHC, fully seen components, unseen TCR plus unseen pMHC, and strictly completely unseen TCR/peptide/HLA. These use exact sequence identity against eligible full-chain training rows, irrespective of label. TCR identity is the ordered full alpha/beta pair, HLA identity is the supplied HLA sequence, and pMHC identity is the peptide/HLA-sequence pair. Strict completely unseen means all three components are unseen. Do not assume the supplied categories have these definitions; report the supplied and derived groups separately. Unseen combinations are not necessarily unseen individual chains or alleles.
- Undefined AUROC/AUPRC as `null` with a reason for empty or single-class groups; never substitute 0.5 or omit inconvenient categories.
- Cohort counts, evaluation runtime, model/evaluator/checkpoint/data hashes and errors. Runtime is evaluation time, not training time; record measured training time separately in the shared log.

Agent evaluation records execution validity, whether a hypothesis/change was provided, comparable previous runs, validation-loss improvement and AUROC change relative to previous best values. These are evidence about execution and outcomes, not a judgement of scientific reasoning. Metrics are compared only across matching data/evaluator protocols. The evaluator records `pending_agent_interpretation`; the agent then appends its own decision and reasoning. A lower MSE is not an automatic keep decision.

**Never evaluate test data in the autonomous optimisation loop.** Validation is the default. Final test evaluation requires an explicit authorised final step with `--split test --allow-final-test`, after model and preprocessing selection is frozen. Do not feed final test results back into further model selection. External IMMREP results must also remain outside iterative optimisation; labels already influenced by IMMREP relabelling cannot support claims of an untouched independent IMMREP benchmark.
